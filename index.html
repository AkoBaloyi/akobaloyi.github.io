The question I am chasing

How can AI help a security team recognise a real threat in a large amount of system activity, and give the team enough evidence to decide what to do next?

Why this question, and why here

The City of Johannesburg deployed Microsoft Security Copilot across its security operations centre on the recommendation of its managed SOC partner, the Council for Scientific and Industrial Research (CSIR) Information and Cyber Security Centre. Microsoft's customer story on the City of Johannesburg and Security Copilot describes a hybrid IT and operational technology estate that lacked the unified visibility and specialist capacity to respond at scale, and reports that Security Copilot agents automate alert triage and cut false positives by up to 95% (Microsoft Customer Stories, 16 April 2026).

Those numbers are vendor-reported. Before treating them as evidence, I would want to know how false positives were measured and whether genuine threats were missed in the same period, which is what the projects below are meant to teach me.

Proposed · Not Built Yet

Seed project 1: Network threat detection experiment

Project question: How well can a simple model identify labelled attack traffic, and what do its false alarms and missed attacks reveal about its usefulness?

Data: CIC-IDS2017, the intrusion detection evaluation dataset published by the Canadian Institute for Cybersecurity at the University of New Brunswick. It holds labelled network flows covering benign activity and several attack types. See the CIC-IDS2017 dataset page at the Canadian Institute for Cybersecurity.

Scope: An offline learning experiment on public data. Nothing here runs against a live network.

Method:

  1. Inspect and prepare the data in Python with pandas: check the labels, the missing and invalid values, the duplicate records and the balance between benign and attack traffic, and write down every cleaning decision.
  2. Set up a fair comparison before tuning anything: hold the test data back first, keep related or duplicate records from leaking across the split, check whether identifiers are revealing the dataset setup rather than attack behaviour, and fit preprocessing on the training data only.
  3. Build a simple baseline: compare a majority-class baseline against a decision tree, and only add a random forest if there is time to evaluate the difference properly.
  4. Examine the mistakes: precision, recall, F1-score and a confusion matrix, which attacks get missed, which benign events get flagged, and where the data allows it, results broken down by attack type.

Outcome: a reproducible analysis that explains its own errors and limitations. Deliverable: a notebook plus a short findings report.

Limitation I am not going to hide: doing well on this dataset would be evidence about the experiment. It would not show that the model can protect a live network or recognise an attack it has not seen before.

Proposed · Follows Project 1

Seed project 2: What the alert actually tells the analyst

Project question: How can a team show that AI is finding more genuine threats rather than simply producing fewer alerts?

Approach: Take the events project 1 flagged and generate a short "why was this flagged" summary for each one: the few features that moved the decision, the records it resembles, and whether the label turned out to be correct. Then read those summaries against the known labels and judge whether they would give an analyst a useful starting point.

Outcome: a short written assessment of whether the evidence is good enough to act on, with the cases where it misleads written up next to the cases where it works.

Depends on project 1: this needs project 1's flagged events and its error analysis as input, so it is the step after, not a parallel idea.

Skills to Grow

Technical

Evaluating a classification model in Python

Python is already on my skills list above. What is not on it yet is being able to defend an evaluation: reading precision and recall properly, so I can say how often flagged traffic is actually malicious and how much of the labelled attack traffic the model found. Careful data preparation is part of the same skill, checking the labels and splitting the data before I trust any score.

Why it matters: an AI/ML engineer in cyber defence is judged on the attacks a system misses and the false alarms it creates, not on a single accuracy number.

Soft

Communicating findings to the people who act on them

Turning model output into evidence someone else can use, in writing and in conversation: what the system flagged, why, how sure it is, and what it cannot tell you. A detection an analyst cannot interpret does not help the analyst.

Why it matters: an AI/ML engineer specialising in cyber defence is measured by whether an analyst can act on what the model flags, not by whether the model scored well in isolation.
